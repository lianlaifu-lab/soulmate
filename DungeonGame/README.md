# 微光地牢 v0.3.1：模块化项目

这次只做结构重构：保留 v0.3 的移动、鼠标射击、双摇杆、三类敌人、障碍物绕行、60 秒试炼、暂停和死亡重开。没有增加武器、关卡或调整难度。

## 第一次打开：Windows + VS Code

1. 保留旧版单文件作为备份。把压缩包完整解压到新文件夹，不能只取出 index.html。
2. 在 VS Code 点击 File → Open Folder，选择包含 index.html、js、css 和 serve.py 的 DungeonGame 文件夹。只信任这个项目文件夹即可。
3. 这次采用 JavaScript ES Modules。建议通过本地 HTTP 服务预览，不要双击 index.html 以 file:// 方式运行。
4. 点击 Terminal → New Terminal（终端 → 新建终端）。终端路径应当是当前 DungeonGame 文件夹。
5. 输入：

```powershell
python serve.py
```

如果系统找不到 python，但安装了 Windows Python 启动器，可以用：

```powershell
py serve.py
```

6. 保持终端运行，在 VS Code 内置浏览器地址栏输入：

```text
http://127.0.0.1:8000/index.html
```

可以先点击 index.html 右上角的小地球打开浏览器面板，再把该面板地址栏换成上面的地址。如果没有浏览器面板，按 Ctrl+Shift+P，执行 Browser: Open Integrated Browser。也可以直接在 Chrome 或 Edge 中打开这个地址。
7. 看到“v0.3.1 · 模块化版”后点击“开始战斗”。先点击游戏画面再按 WASD，按住鼠标左键射击。

Python 只负责把文件提供给浏览器，不负责游戏逻辑。没有 Python 时，也可以使用 Microsoft Live Preview 等本地预览扩展提供 HTTP 服务。这个项目运行不需要 Node.js、不需要 npm install、不需要构建。

## 每次修改后的操作

- 修改相应模块 → Ctrl+S 保存 → 点击游戏预览里的刷新按钮。
- 修改 JS/CSS 不用重启 Python 服务。本项目没有自动热更新，保存之后需要刷新。
- 刷新页面会重新开始整局；仅切换到代码编辑器可能触发暂停，回到画面点击“继续游戏”。
- 运行时入口始终是 index.html。不要把敌人或武器 JS 文件当成网页打开。
- 关闭终端或按 Ctrl+C 会停止本地服务，下次开发重新运行 python serve.py。

## 模块如何协作

index.html 用 `<script type="module" src="./js/main.js"></script>` 加载 main.js。main.js 通过明确的 import 语句加载输入、更新与绘制模块。

每帧 game.js 按原版顺序调用玩家移动、刷怪、敌人状态机和子弹更新。renderer.js 读取状态并绘制。所有模块共享 state.js 导出的 game 对象，因此它们看到的是同一个玩家、同一组敌人和同一个计时。

这个阶段采用小型项目适用的共享状态方式，没有引入框架、构建工具或第三方游戏库。模块间没有循环依赖。不要在各模块复制一份 player 或 enemies，否则会产生相互不同步的数据。

## 第一个安全的修改示例

打开 js/config.js，找到 CONFIG 中的 `speed:210`，改为 `speed:240`。保存并刷新，可以看到玩家移动加快。要恢复就改回 210。

修改玩家速度不会自动改变敌人速度；敌人速度在同一文件的 TYPES 中分别设置。

注意：房间大小与网格尺寸现在仍有固定常数。不要只修改 CONFIG 的 width/height 就期望整个关卡自动调整。下一次开发多房间时再统一这一接口。

## 常见问题

- **页面只有背景、按钮无效**：确认预览地址是 http://127.0.0.1:8000/index.html，且 js 文件夹完整。
- **显示旧版**：检查地址栏是否仍然指向旧 HTML；新页面右上角应显示 v0.3.1。
- **端口占用**：运行 `python serve.py --port 8001`，然后打开 http://127.0.0.1:8001/index.html。
- **无法连接 localhost**：检查终端中服务是否仍在运行，端口是否一致。
- **手机打不开电脑的 localhost**：127.0.0.1 指当前设备。本服务只监听本机；手机测试应使用部署后的网址，或另行配置局域网预览。
- **上传 GitHub Pages**：保持 index.html、css、js 的相对位置，把项目内容放到发布目录。serve.py 不需要在 GitHub 运行。
